# Техническое Задание: PixieTasks — Платформа Микрозаданий

## 1. Обзор проекта

**PixieTasks** — веб-платформа для публикации и выполнения микрозаданий среди школьников Украины.
Платформа обеспечивает безопасные финансовые транзакции через холдирование средств и систему арбитража.

---

## 2. Технологический стек

| Слой | Технология |
|------|-----------|
| Фронтенд | React 18, Vite, TailwindCSS, Zustand, React Router v6 |
| Бэкенд | Node.js 20 + Express.js |
| База данных | SQLite (better-sqlite3) — легко разворачивается без инфраструктуры |
| Аутентификация | JWT (jsonwebtoken) + bcrypt |
| Real-time | WebSockets (ws) |
| Фоновые задачи | node-cron |
| Платежи | Mock Payment API (симуляция) |
| Файлы | multer (загрузка видео) |

## 3. Структура базы данных

### Таблица `users`
```sql
id INTEGER PRIMARY KEY AUTOINCREMENT
nickname TEXT UNIQUE NOT NULL
password_hash TEXT NOT NULL
role TEXT DEFAULT 'user'           -- 'owner' | 'moderator' | 'user'
city TEXT
school TEXT
card_number TEXT                   -- номер банковской карты
balance REAL DEFAULT 0             -- внутренний баланс (холд)
created_at DATETIME DEFAULT NOW
```

### Таблица `tasks`
```sql
id INTEGER PRIMARY KEY AUTOINCREMENT
creator_id INTEGER REFERENCES users(id)
executor_id INTEGER REFERENCES users(id)
title TEXT NOT NULL
description TEXT NOT NULL
city TEXT NOT NULL
school TEXT NOT NULL
amount REAL NOT NULL               -- сумма вознаграждения (мин. 10 грн)
status TEXT DEFAULT 'pending_moderation'
-- Статусы: pending_moderation | on_moderation | approved_awaiting_payment |
--          active | in_progress | pending_confirmation | disputed | completed | rejected | expired
moderator_id INTEGER               -- назначенный модератор
moderator_comment TEXT
held_amount REAL DEFAULT 0         -- замороженная сумма
timer_expires_at DATETIME          -- таймер 48ч для активного задания
dispute_expires_at DATETIME        -- таймер 48ч для спора
appeal_expires_at DATETIME         -- таймер 24ч для апелляции исполнителя
created_at DATETIME DEFAULT NOW
updated_at DATETIME DEFAULT NOW
```

### Таблица `messages`
```sql
id INTEGER PRIMARY KEY AUTOINCREMENT
task_id INTEGER REFERENCES tasks(id)
sender_id INTEGER REFERENCES users(id)
content TEXT
video_url TEXT                     -- путь к видео-подтверждению
type TEXT DEFAULT 'text'           -- 'text' | 'video' | 'system'
created_at DATETIME DEFAULT NOW
```

### Таблица `notifications`
```sql
id INTEGER PRIMARY KEY AUTOINCREMENT
user_id INTEGER REFERENCES users(id)
title TEXT NOT NULL
body TEXT NOT NULL
type TEXT                          -- 'task' | 'payment' | 'dispute' | 'system'
task_id INTEGER
is_read INTEGER DEFAULT 0
created_at DATETIME DEFAULT NOW
```

### Таблица `payments`
```sql
id INTEGER PRIMARY KEY AUTOINCREMENT
task_id INTEGER REFERENCES tasks(id)
payer_id INTEGER REFERENCES users(id)
payee_id INTEGER REFERENCES users(id)
amount REAL NOT NULL
type TEXT                          -- 'hold' | 'release' | 'refund' | 'commission'
status TEXT DEFAULT 'pending'      -- 'pending' | 'completed' | 'failed'
mock_transaction_id TEXT
created_at DATETIME DEFAULT NOW
```

## 4. API Эндпоинты

### Auth
- `POST /api/auth/register` — регистрация
- `POST /api/auth/login` — вход
- `GET /api/auth/me` — текущий пользователь

### Profile
- `PUT /api/profile` — обновить профиль (город, школа, карта)

### Tasks
- `GET /api/tasks` — список активных заданий (с фильтрами)
- `POST /api/tasks` — создать задание
- `GET /api/tasks/:id` — детали задания
- `POST /api/tasks/:id/take` — взять задание
- `POST /api/tasks/:id/confirm` — подтвердить выполнение
- `POST /api/tasks/:id/reject` — отклонить выполнение
- `POST /api/tasks/:id/appeal` — подать апелляцию
- `POST /api/tasks/:id/pay` — внести предоплату

### Moderation
- `GET /api/moderation/queue` — очередь модерации
- `POST /api/moderation/:id/approve` — одобрить
- `POST /api/moderation/:id/reject` — отклонить
- `POST /api/moderation/:id/pass` — передать другому
- `GET /api/moderation/disputes` — список споров
- `POST /api/moderation/disputes/:id/resolve` — разрешить спор

### Messages
- `GET /api/messages/:taskId` — история чата
- `POST /api/messages/:taskId` — отправить сообщение
- `POST /api/messages/:taskId/video` — загрузить видео

### Notifications
- `GET /api/notifications` — список уведомлений
- `PUT /api/notifications/read` — отметить прочитанными

### Admin (Владелец)
- `GET /api/admin/users` — список пользователей
- `PUT /api/admin/users/:id/role` — изменить роль
- `GET /api/admin/stats` — статистика платформы

## 5. Бизнес-логика (Flows)

### Flow 1: Создание и публикация задания
```
Заказчик создает → pending_moderation
Назначается модератор → on_moderation
Модератор одобряет → approved_awaiting_payment + уведомление заказчику
Заказчик вносит предоплату (холд) → active + таймер 48ч
```

### Flow 2: Выполнение задания
```
Исполнитель берет → in_progress + уведомление заказчику + открывается чат
Исполнитель загружает видео → pending_confirmation
Заказчик подтверждает → completed + выплата исполнителю (минус 20% комиссия)
```

### Flow 3: Спор
```
Заказчик отклоняет видео → таймер 24ч для исполнителя
Исполнитель подает апелляцию → disputed + деньги заморожены
Модератор изучает → решение в пользу исполнителя или заказчика
Если 48ч без решения → автовозврат заказчику
```

## 6. Комиссионная модель

- Комиссия Pixie (владельца): **20%** от суммы задания
- Карта владельца прописана в `.env`: `OWNER_CARD=4441111122223333`
- При выплате: сумма × 0.8 → исполнителю, сумма × 0.2 → владельцу

## 7. Требования к UI/UX

- Mobile-First адаптивный дизайн
- Визуальный обратный отсчет (таймер) над каждым заданием
- Красная точка-индикатор непрочитанных уведомлений и сообщений
- Плавные анимации (slide-in, fade, pulse)
- Иконка чата появляется слева снизу при активном задании
- Все формы с валидацией в реальном времени
